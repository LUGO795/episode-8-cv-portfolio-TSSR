Objectif de l'épisode

Un diplôme, c'est une ligne sur un CV. Un titre professionnel bien présenté devient une preuve.
Vous allez construire la section Formation : une grande carte pour le titre TSSR et ses blocs de compétences, une liste de certifications où chaque médaille a sa couleur et un nuage de qualités. Et vous allez corriger le bug du lien actif de l'épisode 5 :

Partie 2

Objectif pédagogique

À la fin de cet épisode, vous serez capable de diagnostiquer un conflit de styles,
de le corriger avec une classe plutôt qu'avec du style en JavaScript
et de construire une section de cartes avec une grille imbriquée.

Ce que vous saurez faire

  • Expliquer pourquoi un style en ligne perd contre une déclaration !important.
  • Départager deux déclarations !important grâce à la spécificité.
  • Poser ou retirer une classe avec classList.toggle(nom, condition).
  • Signaler le lien actif aux lecteurs d'écran avec aria-current.
  • Combiner une classe de base et une classe de couleur (formation-badge badge-niveau5).
  • Imbriquer une grille Bootstrap dans une colonne et égaliser les hauteurs avec h-100.

Correctif

Le « poids » d'un sélecteur CSS : un identifiant pèse plus qu'une classe, une classe plus qu'une balise. À importance égale, le plus spécifique gagne.

🧩 Le bug et son correctif, côte à côte

    .navbar-nav .nav-link { color: var(--clr-text-soft) !important; }        /* 2 classes, !important */
    .navbar-nav .nav-link.active { color: var(--clr-accent2) !important; } /* 3 classes, !important */
  • Avant : le JavaScript écrivait style="color: …" sans !important. Une déclaration normale perd toujours contre une déclaration !important, même en ligne.
  • Après : le JavaScript pose la classe active. Les deux règles ont !important : la plus spécifique gagne, et c'est la nouvelle (3 classes contre 2).
  • En prime : le CSS garde la main sur l'apparence (couleur, fond, soulignement), et aria-current informe les lecteurs d'écran.

On aurait pu corriger le bug en gardant la couleur en JavaScript, en une seule ligne. Sur une copie de votre fichier, trouvez comment écrire une couleur en style en ligne avec !important en JavaScript. Puis donnez trois raisons pour lesquelles la série a préféré la classe active.

La méthode style.setProperty() accepte un troisième argument, la priorité :

        links.forEach(function (l) { l.style.setProperty('color', l.getAttribute('href') === '#' + cur ? 'var(--clr-accent2)' : '', 'important'); });

Un style en ligne !important l'emporte sur une règle de feuille de style !important : le lien passe en bleu. Mais la classe reste meilleure :

  1. Séparation des rôles : le JavaScript dit quel lien est actif, le CSS décide de son apparence. Changer la couleur ne demande pas de toucher au script.
  2. Plus d'effets : une classe déclenche d'un coup la couleur, le fond et le soulignement ; en JavaScript, il faudrait écrire chaque propriété.
  3. Accessibilité : le correctif ajoute aussi aria-current ; une couleur seule ne dit rien aux lecteurs d'écran.

Gardez votre fichier principal identique au code de la série.
